# 旧玩法逻辑迁移与清理方案

> 状态：迁移准备文档，尚未实施。本文记录已调查的依赖和拟议步骤；实施前需重新核对工作区、场景、引用与用户授权。
>
> 已确认的场景处理方向：删除 `Assets/Scenes/SampleScene.unity`，不迁移或保留其旧单人玩法。删除场景及其 `.meta` 会移除该场景 GUID；实施时还需清理 Build Settings 中的对应条目。

## 一、目标与范围

将正式竞技场中残留的旧 `PlayerController` / `GameManager` 单人玩法链路解除、迁移和清理，保持当前 Arena 玩法功能。先替换仍在使用的兼容功能，再清理组件和脚本，避免编译错误、Missing Script 和失效 UnityEvent。

当前竞技场的目标链路：

```text
LocalPlayerInput
       ↓
MatchCoordinator — 对局、体力和移动调度
       ↓
ArenaCharacter — 角色移动、转向与危险物接触
       ↓
ArenaGameUI / CoinSpawner / NpcController
```

### 不属于本轮的默认范围

- 不改变当前竞技场的移动、冲刺、体力、战斗和胜负规则。
- 不删除或修改 QFramework 插件源码。
- 不直接重建竞技场场景、Prefab、模型资源或其 `.meta`。
- 不仅因类型名称与旧玩法有关就删除 `GameArchitecture`、`GameModel` 和相关测试；先检查迁移后的实际用途，再单独决定是否清理。
- 不自动提交、推送或发布。

## 二、当前依赖与风险

调查时 `Assets/Scenes/ArenaScene.unity` 中旧 `PlayerController`、`GameManager` 和 `GameUI` 均禁用，而 `MatchCoordinator` 和 `ArenaGameUI` 启用。`Assets/Scenes/SampleScene.unity` 仍启用旧链路；该场景在 Build Settings 中有一条未启用的记录。

| 对象 / 脚本 | 当前依赖 | 迁移风险 |
| --- | --- | --- |
| `Assets/Scripts/PlayerController.cs` | Arena 中禁用，SampleScene 中启用；`PlayerDirectionIndicator` 读取其 `LastMoveDirection` | 直接删除会影响编译和场景组件引用 |
| `Assets/Scripts/GameManager.cs` | Arena 中禁用，SampleScene 中启用；旧 UI、金币和障碍代码引用 | 直接删除会引发代码错误及旧场景事件失效 |
| `Assets/Scripts/GameUI.cs` | Arena 中禁用，与启用的 `ArenaGameUI` 同在 GameCanvas；SampleScene 中启用 | 误删 GameCanvas 或共享子对象会破坏新 UI |
| `Assets/Scripts/PlayerDirectionIndicator.cs` | Arena 玩家方向指示对象挂载；`ArenaCharacter.Initialize` 查找并禁用旧组件后取得 `Arrow` | 必须先替代箭头引用，不能一起删除方向箭头对象 |
| `Assets/Scripts/Obstacles/PlayerHazardCollision.cs` | Arena 中禁用，SampleScene 中启用；`ArenaCharacter.Initialize` 仍查找并禁用它 | 需先去除 Arena 兼容引用，保留新角色危险物处理 |
| `Assets/Scripts/CoinPickup.cs` | Arena 中有 10 个未激活旧金币对象挂载；SampleScene 中也有实例 | 要确认旧对象和字段不被其他功能引用；不能误改共享 FBX 源资源 |
| `Assets/Scripts/Obstacles/ObstacleBehaviour.cs` | 同时支持 Arena `BindArena` 与旧 `GameManager` | 移除旧分支前需验证移动障碍与尖刺的运行、暂停行为 |
| `Assets/Scripts/Obstacles/LethalContact.cs`、`LethalObstacle.cs` | Arena 场景保留相关组件，`MatchCoordinator.IsHazard` 使用其类型识别危险物 | 不能直接删除；必须先保留或迁移危险物识别能力 |
| `Assets/Tests/PlayMode/GameFlowTests.cs` | 直接通过反射测试旧 `GameManager` | 需要迁移仍适用的行为测试，不能留下无法运行的旧测试 |
| `Assets/Scripts/Architecture/`、`Assets/Scripts/Models/GameModel.cs` | 旧管理器/UI 和若干 EditMode 测试引用 | 保留到完成用途审查，不因为清理控制器而直接删除 |

`SampleScene` 包含旧暂停、继续、重开、返回菜单和设置等 UnityEvent 绑定；其场景删除会一并移除这些旧绑定。Arena 的新 UI 绑定须分别核对，不能认为两者相同。

## 三、实施前检查与基线

1. 检查 Git 工作区和暂存区，保留用户及其他协作者的改动；不擅自回退、覆盖或提交。
2. 确认 Unity 处于 Edit Mode，记录已加载场景及未保存更改；不得覆盖当前场景工作。
3. 在 `Assets/Scenes/ArenaScene.unity` 核查玩家、方向箭头、旧金币、危险物、障碍、GameCanvas 组件及 Prefab 来源 / 场景覆盖。
4. 记录实际运行基线：普通移动、转向惯性、体力和冲刺、NPC 寻路、金币、障碍与击退、暂停恢复、重开、返回菜单和对局结束。
5. 查找旧脚本的代码及序列化使用，包括场景、Prefab、ScriptableObject、UnityEvent 和 AnimationEvent；确认资产引用索引的时效。动态 / 字符串引用需另行搜索。
6. 确认适用 EditMode / PlayMode 测试可发现并记录当前结果；测试发现、编译和测试通过分别记录。
7. 再次核对 `SampleScene` 的场景引用、Build Settings 条目及删除后果；不因静态检索为零就假定不存在所有动态加载方式。

## 四、分阶段实施计划

### 阶段 1：解除 Arena 对旧角色组件的依赖

#### 方向指示

- 修改 `Assets/Scripts/Gameplay/Characters/ArenaCharacter.cs` 的 `Initialize`，不再依赖 `PlayerDirectionIndicator` 获取箭头；改为明确的箭头引用或检查过的层级查找。
- 从 Arena 玩家方向指示对象移除旧 `PlayerDirectionIndicator` 组件，保留 `Arrow` 对象、材质、旋转逻辑及外观。
- 验证玩家和运行时创建的 NPC 的方向箭头不丢失，方向与实际移动一致。

#### 旧危险碰撞

- 从 Arena 玩家对象移除已禁用的 `PlayerHazardCollision` 组件。
- 移除 `ArenaCharacter.Initialize` 中专门查找、禁用该旧组件的兼容代码。
- 保留 `ArenaCharacter` 当前的控制器碰撞、触发器、危险物接触去重、保护时间和击退处理。

### 阶段 2：迁移障碍与金币旧链路

#### 障碍

- 检查并修改 `Assets/Scripts/Obstacles/ObstacleBehaviour.cs` 的 `CanRun` 与 `BindArena`，移除对旧 `GameManager` 的依赖，同时保留竞技场对局状态与暂停规则。
- 检查 `Assets/Scripts/Obstacles/LethalContact.cs`、`Assets/Scripts/Obstacles/LethalObstacle.cs` 和 `Assets/Scripts/Gameplay/Match/MatchCoordinator.cs` 的 `IsHazard`；保留或迁移 Arena 依赖的危险物标识及尖刺激活判定，移除只用于旧管理器的一次性致死行为。
- 移除任何序列化字段或组件前，先检查当前值、引用和可迁移的数据。不要直接删除整个障碍体系。
- 验证固定障碍、移动障碍、尖刺激活、暂停、受击、保护时间和击退。

#### 旧金币

- 检查 Arena 中旧金币对象及 `CoinPickup` 的全部场景引用，确认是否还被 `CoinSpawner`、UnityEvent 或其他对象使用。
- 仅在确认无用途后移除对应场景实例组件或专属旧对象；保留当前 `CoinSpawner` 的动态金币、预警、拾取和掉落功能。
- 区分场景实例和源 FBX；不因清理场景组件而修改共享 FBX 或其 GUID。

### 阶段 3：清理旧场景、组件及脚本

先确认阶段 1–2 的新链路能够正常工作，再执行：

1. 通过 Unity Editor API 从 Build Settings 移除 `Assets/Scenes/SampleScene.unity` 条目。
2. 删除已确认不再保留的 `Assets/Scenes/SampleScene.unity` 及其 `.meta`，明确该场景 GUID 将被移除。
3. 从 Arena 场景移除已禁用且不再需要的旧 `PlayerController`、`GameManager`、`GameUI` 组件；仅在确认对象没有其他用途时清理其专属对象。
4. 复查旧脚本的代码引用、场景 / Prefab 使用、UnityEvent 和 AnimationEvent；不依赖单一引用索引覆盖所有动态引用。
5. 在确认无剩余依赖、相关能力已替代后，删除以下旧脚本及其 `.meta`：
   - `Assets/Scripts/PlayerController.cs`
   - `Assets/Scripts/GameManager.cs`
   - `Assets/Scripts/GameUI.cs`
   - `Assets/Scripts/PlayerDirectionIndicator.cs`
   - `Assets/Scripts/Obstacles/PlayerHazardCollision.cs`
   - `Assets/Scripts/CoinPickup.cs`

删除脚本及 `.meta` 会移除对应 GUID；必须先完成引用清理和用户明确授权，不能用删除重建方式替代结构化迁移。对仍有用途的脚本或资产应暂停删除并说明。

### 阶段 4：测试迁移与遗留架构审查

- 分析 `Assets/Tests/PlayMode/GameFlowTests.cs` 覆盖的暂停、伤害、拾取、胜负和重开语义；先确认哪些适用于 Arena，再为当前实现增加或调整测试，最后清理专门依赖旧 `GameManager` 的测试。
- 保留并运行适用的 `Assets/Tests/EditMode/` 与 `Assets/Tests/PlayMode/` 测试，按实际发现和结果报告。
- 审查 `GameArchitecture`、`IGameModel`、`GameModel`、`CollectCoinCommand` 与相关测试的剩余用途，列出保留原因或另行提出删除方案；本轮不默认移除 QFramework 通用架构及插件。
- 检查所有相关场景无 Missing Script、无失效 UnityEvent，运行时 Console 无新增错误。
