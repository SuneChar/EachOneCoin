# 移动基线采集使用说明

本采集器只记录移动相关数据，不记录攻击指标，不修改移动速度或 AI 决策。默认关闭；仅在创建 Arena 对局时检测开关。

## 开启和关闭

在启动 Unity 编辑器或游戏进程前，设置环境变量 `EACHONECOIN_MOVEMENT_TELEMETRY=1`；或者在进程启动命令中加入 `--movement-telemetry`。之后进入 `Assets/Scenes/ArenaScene.unity`，开始一场对局。关闭方式是移除环境变量/参数并重新启动进程；已开始对局不会动态切换。

例如在 PowerShell 中设置当前终端及其子进程的环境变量：

```powershell
$env:EACHONECOIN_MOVEMENT_TELEMETRY = '1'
# 从此终端启动 Unity 编辑器或游戏进程
```

环境变量只影响继承它的进程，不会自动影响已经运行的 Unity 编辑器。不要将此开关用于未告知参与者的采集。

## 文件

每场对局写入 `Application.persistentDataPath/MovementTelemetry/<随机场次ID>.jsonl`。文件为 UTF-8，每行一个 JSON 事件，无上传功能。具体路径因平台和产品设置不同而不同；Unity 编辑器中可通过 `Application.persistentDataPath` 查询。

- `match_start`：实际移速、场景、平台、分辨率、相机 FOV 和本地位置。
- `movement`：约 10 Hz，每角色一条。`dt` 为样本间有效对局时间；`x`、`z` 为世界坐标，`speed` 为水平位移除以 `dt`。`valid_speed=false` 时不要使用速度；`knocked_back=true` 的样本应单独分析。玩家样本包含采样时的输入；NPC 样本包含到玩家的距离、距离变化速度（正值代表远离）、路点状态、视口坐标与深度。仅当 `valid_relative_speed=true` 时使用距离变化速度。`visible` 仅表示投影点在视口内且位于相机前方，不代表未被遮挡。
- `input`：检测到玩家方向输入变化时记录。方向为采集时读取的输入，不是独立设备类型。
- `npc_event`：`path_failed` 为寻路失败，`blocked_retry` 为代码检测到移动受阻后重试；事件还标记当时是否受击退影响。
- `pause` / `resume`：暂停与恢复。恢复后重置采样基准，不跨暂停计算速度。
- `match_end`：`timeout` 为计时结束，`finished_unknown` 为其他正常结束，`interrupted` 为卸载或退出。因异常终止没有结束事件的文件不应作为完整对局。
- `buffer_overflow`：有记录因缓冲区上限丢失；该场采集不完整。

`game_time` 仅在采集器观察到对局进行且未暂停时累计；`real_time` 为进程单调时钟的相对时间。日志约每秒刷新，进程崩溃或被强制终止可能丢失最后一段数据。写入失败时采集器停止并输出警告，不阻断游戏。

## 分析限制

- 10 Hz 采样只能观察总体运动，不足以准确测量短于采样间隔的屏幕横穿时间或识别全部短暂状态。
- 样本是采样间隔内的平均位移速度，而非瞬时速度；快速往返可能相互抵消。角色传送或采样期间状态变化时，速度标记为无效。
- 路点是采样时状态；路点刚被清除、碰撞、寻路重试和受击都可能影响移动，不能简单把低速视为卡死。
- `npc_event` 是原始事件，未实现自动三秒疑似停滞统计，也未实现碰撞原因分类或自动汇总报告；需要结合事件、时间、状态和样本离线分析。
- 屏幕坐标和距离变化速度可供离线计算屏幕位移；采集器不直接计算横穿 100 像素耗时。视口坐标按画面宽高归一化，不等同像素。
- 输入变化是逐帧观察结果，不能推断未被 Unity 输入系统采样到的操作。日志不包含设备类型、参与者身份、攻击或胜负分析。
- 当前为文件缓冲后定期同步写入；尚需在目标设备做帧时间与 GC 对比，确认采集对性能的影响。
